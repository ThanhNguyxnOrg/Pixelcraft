Leader Completeness & WAL Frame Safety in Local Replicas

Raft guarantees that if a log entry is committed in a given term, that entry stays present in the write-ahead log of every leader for higher-numbered terms [@ongaro2014raft, §5.4.3]. When pairing replicated state machines with offline document merge engines in , monotone term counters guard snapshot compaction boundaries before encrypted frames flush to disk.

// Streams verified WAL commit frames via binary tauri::ipc::Response
#[tauri::command]
pub async fn read_committed_wal(
    note_id: String,
    state: tauri::State<'_, VaultEngine>,
) -> Result<tauri::ipc::Response, VaultError> {
    let frame = state.sqlite_wal.fetch_verified_frame(&note_id).await?;
    debug_assert!(frame.term >= state.committed_term());
    Ok(tauri::ipc::Response::new(frame.decrypted_bytes))
}
