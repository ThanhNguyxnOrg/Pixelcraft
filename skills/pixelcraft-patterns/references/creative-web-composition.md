# Creative web composition patterns

Use these as content/interaction patterns, not as fixed page templates. Select by user task, content material, and product mode.

| Pattern | Structure | Useful details and failure checks |
|---|---|---|
| Editorial hero | Headline + concrete claim + subject visual + next step | Avoid default centered hero/two CTAs/three cards; prove the claim |
| Case-study index | Curated work grid/list with metadata and filters | Preserve project labels, loading, empty, and filter states |
| Project detail | Outcome/context → role → process → artifact → result | No fabricated metrics; make long-form reading work without motion |
| Product story | Problem/material → features → proof → demo → purchase/CTA | Keep price/variant/purchase controls accessible if present |
| Interactive product viewer | Semantic details + optional 3D/media region | Renderer failure must not block comparison or purchase |
| Service/capabilities list | Capability groups with explanatory examples | Avoid long undifferentiated ticker lists |
| Testimonial/social proof | Real quote/source/date/attribution | No invented trust signals or fake metrics |
| Pricing | Plans/units/billing cadence/limits/terms | Clarify assumptions, renewal/currency, responsive comparison |
| Contact/lead capture | Clear reason → short form → consent/privacy → confirmation | Preserve values/errors and show submission outcome |
| Narrative chapter | Chapter heading/content + optional persistent artifact | Direct links, normal scroll, static alternative |
| Mega menu | Grouped destinations and clear focus model | Keyboard, touch, Escape, focus restore, viewport height |
| Footer | Navigation/contact/legal and useful end-of-page cue | Avoid decorative motion delaying the next task |

## Section library workflow

Use section-level pattern catalogs for layout rhythm ideas, full-experience interactive showcases for pacing and transitions, and shipped product flow libraries for multi-step states. Convert any reference into a content/interaction recipe rather than copying its composition, branding, or visual assets.

## Acceptance

Every pattern must specify its primary task, key states, semantic controls, responsive changes, localization pressure, and a way to verify behavior.
