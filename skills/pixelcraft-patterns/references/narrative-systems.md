# Narrative systems

## Story before scroll

Write a linear outline before planning a pinned scene. Each chapter needs one claim, evidence/artifact, explanation, transition, and next-step cue. If the story fails as plain text, animation will not fix it.

## Choose a narrative model

| Model | Structure | Useful for |
|---|---|---|
| Artifact + annotations | Persistent image/product/map with chapter-specific highlights | Product explainers, architecture, data context |
| Journey | Origin → milestones → destination | Place-based story, process, travel |
| Time sequence | Ordered moments/eras/seasons | History, day-in-life, transformation over time |
| Before/after | Starting condition → stages → changed result | Manufacturing, service impact, case study |
| Guided exploration | User chooses scene/order and can reset | Exhibitions, portfolios, interactive learning |
| Data narrative | Claim → chart/map → evidence/source → interpretation | Reports and analytical campaigns |

## Chapter contract

Every chapter has a stable ID, heading, concise summary, main content, associated visual state, source/data provenance where needed, and a direct link. Current chapter indication is helpful but should not be the only navigation.

Avoid making scroll progress equivalent to completion or understanding. Provide a table of contents, captions/labels, and a linear route through all evidence.
