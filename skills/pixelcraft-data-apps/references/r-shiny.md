# R Shiny (adjacent data-app ecosystem)

This is not Python, but Shiny belongs in the same rapid data-app decision space. Do not force Python idioms onto reactive R code.

## Token mapping

Use `bslib::bs_theme()` arguments (`bg`, `fg`, `primary`, `base_font`, `heading_font`) and Bootswatch only as a deliberate base. Add scoped custom CSS variables/rules for semantic roles; use `thematic` so plots inherit app colors/fonts where appropriate.

## Layout and responsive idioms

Use `page_sidebar`, `page_navbar`, cards/layout columns and Bootstrap responsivity rather than absolute positioning. Sidebar is for controls, navigation for tasks—do not overload both. Validate narrow/embedded windows.

## Typography/custom fonts

Configure `base_font`/`heading_font` or webfont helpers deliberately. Verify numeric legibility, fallback, localization, plot font matching, scaling.

## Motion/reduced motion

Browser CSS controls most motion. Keep progress/spinner behavior truthful and honor `prefers-reduced-motion` in custom CSS. Reactive invalidation must not masquerade as progress.

## Accessibility specifics

Use headings/landmarks/labels, alt text or text summaries for plots, non-color encodings, keyboard-reachable controls, accessible tables, focus management after dynamic UI. Shiny/Bootstrap maturity does not make arbitrary output accessible.

## States idiom

Reactive dependencies need explicit empty/no-data/error/loading/permission/stale states. Use req/validate/showNotification/progress deliberately; distinguish no rows from query failure. Expensive work needs caching, invalidation, cancellation expectations, and multi-user isolation.

## Forms idiom

Inputs require labels/help/format validation and preserve values across reactivity. Validate timing using dedicated validation patterns/packages or explicit server logic; never clear inputs because another reactive invalidates. Uploaded files need type/size/security feedback.

## Do/don't pairs

| Do | Don't |
|---|---|
| `bs_theme(primary = "#005f73", base_font = …)` | random CSS overriding autogenerated internals |
| explicit `validate()` empty/error message | blank plot/table interpreted as zero data |
| non-color plot encoding | color-only categorical meaning |
| labeled upload/control input | relying on placeholder-like hints |

## Known traps

Reactive loops/invalidation storms, hidden cross-session leakage, long computation blocking worker process, plot/UI theme mismatch, unstable custom CSS, unstable deployment memory/timeouts, treating prototype security as production-ready.

## Verification commands

```sh
Rscript -e 'shiny::runApp()'
Rscript -e 'testthat::test_dir("tests")'
Rscript -e 'shinytest2::test_app()' 2>/dev/null || true
```

Inspect real browser rendering, keyboard/focus, empty/error/large data, concurrent users, upload failure, timeout/memory behavior, responsive zoom/localization.
