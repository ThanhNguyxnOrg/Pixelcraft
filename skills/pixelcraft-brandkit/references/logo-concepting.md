# Logo concepting, mascot design, and scalability

Evidence base: established identity-design principles, platform icon constraints, mascot practice, and small-size reproduction evidence.

## Identity before invention

A logo identifies; it does not explain the whole business. It functions as a flag, signature, or escutcheon and derives meaning from the quality of what it identifies. Evaluate symbols as **appropriate**, **distinctive/memorable**, and **simple**. Use those as hard constraints:

1. **Appropriate** — form and attitude fit category, audience, trust level, and cultural context.
2. **Distinctive** — unusual enough to describe or doodle after one exposure without copying a known mark.
3. **Simple** — uncomplicated enough to reproduce consistently in favicon, app icon, print, motion, embroidery, and UI.

Do not judge a first sketch by whether it “says everything.” Judge whether it can become an empty vessel consistently filled by product behavior and brand use.

## Process: strategy → metaphor → quantity → reduction

1. **Strategy brief.** Write category, audience, product truth, emotional promise, personality in three adjectives, cultural risks, competitive frame, explicit anti-goals, and required existing assets.
2. **Metaphor inventory.** List domain objects, actions, instruments, organisms, rituals, constraints, failure modes, and expert-only details. Prefer product truth over category cliché.
3. **Sketch many before rendering.** Produce at least 20–30 small black-only thumbnail ideas or 5–8 distinct concept families. No color, texture, or gradient until silhouette/meaning work. Record conventional probability and reject the obvious first answer.
4. **Reduce.** Remove one element at a time. If removal does not harm recognition, it stays removed. Merge duplicate metaphors; Microsoft recommends one clear focal metaphor and no more than two in an app icon.
5. **System test.** Test symbol alone, wordmark, lockup, avatar/icon crop, monochrome, reversed, motion behavior, pattern/detail, and localization-neutral meaning.
6. **Context test.** Place beside competitors and inside real surfaces: browser tab, repository avatar, terminal/docs header, mobile home screen, social card, slide footer, sticker/print.
7. **Time test.** Remove trend decoration. Ask whether the core shape survives when gradients, shadows, noise, and current fashion are removed.
8. **Critique externally.** Seek critical discourse beyond launch novelty; review the identity after use/context, not only first-impression praise.

## Sketch matrix

Force divergence across axes before refining:

| Axis | Conservative | Expressive |
|---|---|---|
| metaphor | direct product action | indirect domain ritual/material |
| form | geometric/monogram | organic/character/systemic |
| construction | single shape | negative-space/fused form |
| voice | institutional/native | playful/subcultural/experimental |
| motion behavior | static identity | responsive/generative/mascot actor |

Choose one primary metaphor. A second idea may remain only if it is fused structurally, not pasted beside the first.

## Mascot/character logo rules

Use a mascot when personification, guidance, play, community, or approachability is part of the strategy—not as decoration. Adobe's mascot guidance starts with personality: decide what the character should communicate, then choose object/animal/person/persona accordingly.

- Define three personality adjectives and what the mascot must never become.
- Start with silhouette: fill it solid black; it must be distinguishable at thumbnail size before eyes/props/details are added.
- Give the character one memorable hook: posture, ear/antenna shape, visor, tail, tool, symmetry break, or behavioral trait. More than one hook competes.
- Use posture/expression as system behavior: neutral, success, error, loading, empty state, celebration. Do not redraw a different character each time.
- Keep construction consistent: proportional head/body grid, outline weight, eye geometry, limb/appendage logic, color roles, perspective, and lighting.
- Mascot logo and mascot illustration are separate asset classes. The logo version is the reduced, reproducible silhouette; narrative illustration can carry more detail.
- Avoid culturally insensitive species/roles, random animals, clipart expressions, and “cute” infantilization of serious domains.
- For agent/AI products, a robot is inherently common; it is justified only when the body/face/system behavior encodes a specific product truth rather than generic “AI assistant” imagery.

## Scalability and legibility tests

Run these tests on rendered output, not only the vector artboard:

| Test | Pass condition |
|---|---|
| silhouette | recognizable when filled black and viewed at thumbnail size |
| doodle/memory | a viewer can roughly draw or describe it after a short exposure |
| 16 px | core silhouette survives; internal detail may disappear intentionally |
| 32 px | primary focal metaphor reads; no text required |
| 64 px | secondary detail begins to resolve without changing the shape |
| app icon | simple central idea, minimal shapes, no nonessential words |
| monochrome/reverse | identity survives without gradient/color dependence |
| optical alignment | visual center/balance checked; geometry alone is not enough |
| truncation | long translations/labels do not depend on icon text |
| motion/reduced motion | recognizable first/last frame; movement not required for meaning |
| context | legible on light/dark/photo backgrounds with defined clearspace |
| consistency | every touchpoint uses the same construction rather than local variants |

If small sizes fail, do not merely zoom in. Create a sanctioned small-size reduction: fewer pixels/details, thicker outline, simplified mouth/eyes/props, or icon-only crop.

## Reduction critique questions

- What is the one thing people should remember?
- Which element is doing no identity work?
- Does the mark depend on rendering effects, color count, or explanation?
- Could a competitor use the same silhouette with a palette swap?
- Does it look like a known trademark or stock icon when squinted at?
- Does the wordmark share the mark's geometry/spacing logic rather than fighting it?
- Is there a documented reason for every asymmetry?
- Is the design robust enough to become boring through repetition—the mechanism by which recognition forms?
