# Reusable reference record

Store observations as compact structured notes in the research artifact or project brief. Do not add live gallery content or third-party screenshots to the Pixelcraft package without permission.

## Record fields

| Field | Required meaning |
|---|---|
| source_url | Exact listing/detail/live URL |
| source_type | Award gallery, section library, product-flow library, live project, documentation |
| project / creator | Public name and attribution where available |
| award / date | Exact label/date if published; otherwise unknown |
| inspection_date | Date this observation was collected |
| scope | Route, viewport, input, and states inspected |
| visual_pattern | Layout/hierarchy/material/motion observation |
| interaction_pattern | User input → state change → feedback → recovery |
| rendering_surface | DOM, SVG, Canvas, WebGL, WebGPU, video, audio, native, or unknown |
| technology_evidence | Exact library/resource plus evidence label |
| transferable_recipe | Original, generalized implementation steps |
| limitations | Performance, accessibility, mobile, licensing, source visibility, unknowns |
| evidence_label | gallery-tagged, metadata-reported, markup-observed, runtime-observed, inferred |

## Recipe quality

A recipe is useful only when it records:
- the user/product purpose, not just an effect name;
- trigger and state transitions;
- required semantic DOM and input alternatives;
- implementation options and version-sensitive checks;
- reduced-motion, error, loading, and unsupported-device behavior;
- performance budget and a concrete verification action.

## Comparison

Compare references by task fit, interaction clarity, distinctiveness, responsiveness, accessibility, implementation cost, and evidence confidence. A high award score does not override product constraints.
