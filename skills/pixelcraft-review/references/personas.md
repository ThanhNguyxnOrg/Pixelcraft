# Persona walkthrough protocol

Personas are hypothesis generators, not simulated users and not evidence of actual human behavior.

## Walkthrough cast

| Persona lens | Force through the walkthrough |
|---|---|
| confused novice | no domain knowledge; relies on recognition/help; misunderstands jargon |
| impatient expert | keyboard/bulk/shortcut path; repeats task; notices latency/friction |
| screen-reader user | semantic name/order/state/status; no visual-only grouping |
| one-hand mobile user | reach/occlusion/interruption/small target/network switching |
| slow/offline network user | loading, stale cache, retry, duplication, background completion |
| non-native/RTL user | translation expansion, reading direction, formality, locale formats, IME |
| stressed/rushed user | low working memory, interruptions, error recovery, irreversible action risk |
| accessibility-dependent user | zoom, high contrast, reduced motion, switch/voice/controller input |

## Protocol

1. Pick 2–4 relevant lenses; do not perform theatrical personas unrelated to risk.
2. Write the exact task, entry point, context, constraints, and success criterion.
3. Step through without author knowledge. At each step record: what is perceived, what is ambiguous, expected next action, actual affordance, failure/recovery path.
4. Mark outputs as hypotheses. Promote to findings only when supported by code, rendered inspection, deterministic behavior, or strong platform evidence.
5. State what remains unverified because a real assistive technology/device/user was unavailable.

Do not use personas to launder taste (“the expert would find this ugly”). Use them to expose missing cues, memory burden, unsafe assumptions, and recovery failures.
